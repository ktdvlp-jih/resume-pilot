## 자기소개서

직무 경험 및 역량
화학물질관리시스템(CMS) 구축과 운영, 고객사별 커스터마이징을 맡아 왔습니다. Spring Framework, JSP, MSSQL, MyBatis로 규제와 현장 절차를 시스템에 넣었고 구축 후에도 유지보수와 기능 개선을 이어 갔습니다. ERP나 그룹웨어와 붙일 때는 값을 받기만 하지 않았습니다. CMS 규격에 맞게 정제해서 규제 대응과 현업이 실제로 쓰게 만드는 일이 제 일이었습니다.
애경케미칼 CMS 고도화가 그렇습니다. 기존 CMS와 ERP 인벤토리를 분석하고 정제한 뒤 이관했고 SAP는 REST로 자재 정보와 창고 보관량을 받아 규제 대응과 보관 제한 검증에 연결했습니다.
VOC는 전자정부프레임워크 레거시를 Spring Boot 백엔드와 React, JPA로 나누는 전환에 참여했습니다. 기존 기능은 유지한 채 API만 다시 정리했습니다.
매트릭스투비에서는 이기종 DB Conversion에 참여했고 관세청 전자문서와 공지를 모아 조회하고 수정한 뒤 검증하는 플랫폼을 구축했습니다.
개인으로는 RAG로 경험과 채용공고를 묶어 자소서를 만드는 플랫폼을 설계하고 구현했습니다. 그누보드 자사몰은 주문과 결제까지 연결했습니다. 신랑/신부 전용 URL로 사진과 체형, 의상을 받아 AI로 합성하고 생성하는 서비스를 만들었습니다. 회사 업무의 연동과 운영을 개인 프로젝트에 적용하면서 다루는 기술을 넓혔습니다.

협업 및 성과
애경케미칼 CMS 고도화가 가장 크게 남습니다. 고객사 그룹웨어와 내부 시스템이 바뀌면서 기존 CMS를 그 환경에 맞게 고쳐야 했습니다. 인벤토리는 기존 CMS와 ERP 자재/성분 데이터를 비교하고 정제한 뒤 새 CMS로 옮겼고, SAP는 REST로 붙였습니다.
연동용 I/F 정의서를 직접 썼고, 고객사와 타사 담당자와 데이터 항목, 전송 시점, 예외 처리를 맞춰 갔습니다. SAP MM 자재 정보는 규제 대응과 위험성 평가에, WMS 창고 보관량은 제한 검증에 연결했습니다.
처음에는 데이터 구조와 연동 범위가 분명하지 않았습니다. 내부 개발자, 고객사, 외부 협력사 사이에서 차이를 하나씩 확인하고, 부족한 부분은 스펙과 샘플 데이터로 메웠습니다. 해석이 맞춰진 뒤에는 그 스펙으로 이관과 SAP 연동을 운영에 올렸습니다.

성장과정, 교우 관계 가치관
어릴 때부터 맡은 일은 끝까지 챙기는 편입니다. 학급 임원이나 조별 과제에서도 역할을 미루지 않고 일정과 준비부터 정리했고, 실수가 나오지 않게 미리 점검하는 습관이 생겼습니다.
대학 때는 소프트웨어 동아리에서 다른 동아리와 같이 아두이노 기반 음악 반응형 LED 조명을 만들었고, 교내 대회에서 2등을 했습니다. 그때 기술 구현보다 팀원 사이 일정과 인터페이스를 맞추는 일이 완성도를 가른다는 걸 배웠습니다.
지금도 내가 한 일이 다른 사람에게 피해를 주면 안 된다는 기준은 같습니다. 화학물질 데이터 연동 오류는 현업의 법적, 안전 판단으로 이어지므로, 화면이 돌아가는 것만 보고 넘기지 않고 예외와 누락 데이터를 먼저 확인합니다.

성격의 장단점 (대인관계, 성격, 여러가지 장 단점)
일을 미루지 않습니다. 예외와 연동 실패 가능성까지 몇 번 본 뒤에 다음 단계로 넘깁니다. 규제 판정과 연동 매핑 구간에는 단위 테스트를 넣어, 코드를 고쳐도 기존 로직이 깨지지 않는지 확인합니다. 운영에 올린 뒤에는 같은 문제가 다시 나오지 않게 원인을 남깁니다. 문제가 나면 임시 조치로 끝내지 않고 데이터 흐름과 연동 지점을 다시 봅니다.
다만 새로운 연동이나 도메인을 처음 맡을 때, 전체 구조를 다 파악하고 시작하려다 착수가 늦어진 적이 있습니다. 지금은 전송에 꼭 필요한 항목과 예외 범위부터 정해 두고, 세부 매핑은 문서와 샘플 데이터로 채우면서 동료에게 일찍 의견을 받습니다.
타 부서나 고객사와 스펙을 맞출 때는 감정보다 데이터 정의와 처리 시점을 기준으로 이야기합니다. 의견이 갈려도 그 기준으로 맞춰 가면 일이 덜 꼬입니다.

지원동기 및 입사 포부
CMS를 새로 만들고 운영하면서, 규제와 붙은 데이터가 흔들리지 않게 다루는 일을 해 왔습니다. 기준이 바뀌면 화면과 연동도 같이 바뀌어야 했고, ERP나 그룹웨어와 값이 어긋나지 않게 맞추는 일이 신뢰를 지키는 일이었습니다. VOC 전환에서는 레거시를 유지한 채 서비스 구조를 나누는 작업에 참여했습니다.
업무만으로는 사용자 앞에서 서비스를 끝까지 만들어 본 경험이 부족했습니다. 그래서 개인으로 RAG 자소서 서비스, 결제까지 이어지는 자사몰, 전용 URL로 권한이 나뉘는 영상 제작 서비스를 만들었습니다. 만들면서 인증, 데이터 맞춤, 생성 결과 품질을 직접 확인했습니다. AI는 설계만 맡기지 않고 구현에도 썼고, 나온 코드와 연동, 예외는 직접 읽고 맞췄습니다.
입사 후에도 사용자와 협업자 업무가 끊기지 않는 쪽을 먼저 보겠습니다. 혼자 기능을 늘리기보다 동료와 원인을 나눠 보고, 운영에 올려도 되는 개선을 쌓겠습니다.
