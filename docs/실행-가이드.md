# ResumePilot 실행 가이드

개발은 **터미널에서 각 서비스를 직접 실행**하고, 배포는 **`docker-compose.yml` 하나**로 합니다.

> **기준 OS:** macOS (zsh / bash). Windows는 동등 스크립트(`*.ps1`)를 사용합니다.

---

## 사전 요구사항

| 도구 | 용도 |
|------|------|
| Docker Desktop | PostgreSQL 컨테이너 (개발) / 전체 스택 (배포) |
| Java JDK 21 | `resume-api` |
| Node.js 22 | `resume-web`, `resume-admin` |
| Python 3.12+ | AI 서비스 3개 |

---

## 1. 로컬 개발 (터미널)

### 1-1. 환경 변수

```bash
cd ~/Desktop/Work/resume-pilot   # 실제 클론 경로로 변경
cp .env.example .env.local
# JWT_SECRET 등 필요 시 수정
# 자소서 생성은 외부 AI API 호출. 모델·키는 Admin /admin/llm-settings (서버에 LLM 미설치)
```

각 터미널에서 서비스를 실행하기 전에 아래 스크립트로 `.env.local`을 **현재 셸**에 로드합니다. (`source` 필수 — 직접 실행하면 자식 프로세스에만 적용됨)

```bash
source ./scripts/load-env-local.sh
```

### 1-2. PostgreSQL

로컬에서 API를 띄울 때 DB는 **둘 중 하나**를 씁니다.

#### A) 로컬 Docker DB (완전 로컬)

```bash
docker run -d --name resume-pilot-db -p 5432:5432 \
  -e POSTGRES_DB=resumepilot \
  -e POSTGRES_USER=resumepilot \
  -e POSTGRES_PASSWORD=resumepilot \
  pgvector/pgvector:pg17
```

이미 실행 중이면 `docker start resume-pilot-db`

`.env.local` 예:

```bash
SPRING_DATASOURCE_URL=jdbc:postgresql://localhost:5432/resumepilot
DATABASE_URL=postgresql://resumepilot:resumepilot@localhost:5432/resumepilot
```

#### B) 원격 서버 DB (SSH 터널 — 권장)

서버 Postgres는 보통 호스트 **55532**에 매핑됩니다. 공인망에 DB 포트를 직접 열지 말고 **SSH(22) 터널**로 붙습니다.

| 도구 | 하는 일 |
|------|---------|
| **DBeaver** | 연결 설정의 **SSH** 탭에서 터널 (별도 터미널 불필요) |
| **로컬 `bootRun` / AI 서비스** | DBeaver와 무관 → 터미널에서 `ssh -L`을 **창을 유지한 채** 실행 |

```bash
# 터미널 A — 이 창을 닫지 말 것
ssh -L 55532:localhost:55532 유저@서버호스트
# 또는: ./scripts/resume-pilot.sh tunnel 서버호스트
```

`.env.local`은 **localhost**를 가리키게 둡니다 (실서버 IP를 JDBC에 직접 넣지 않음). 서버 IP·계정은 Git에 커밋하지 않습니다.

```bash
SPRING_DATASOURCE_URL=jdbc:postgresql://localhost:55532/resumepilot
DATABASE_URL=postgresql://resumepilot:비밀번호@localhost:55532/resumepilot?sslmode=disable
```

그다음 다른 터미널에서 `source ./scripts/load-env-local.sh` 후 서비스를 기동합니다.

> DBeaver만 쓸 때는 SSH 탭만으로 충분합니다. **Spring API를 Mac에서 돌릴 때만** 터미널 터널이 필요합니다.

### 1-3. AI 서비스 (터미널 3개)

각 터미널에서 **저장소 루트**에서 env를 로드한 뒤 서비스 디렉터리로 이동합니다.  
이미 `rag-service/` 등이라면 `source ../scripts/load-env-local.sh` 를 쓰세요.  
원격 DB면 **SSH 터널 창을 유지**하고 `.env.local`은 `localhost:55532`여야 합니다 (§1-2 B).

```bash
# 터미널 1 — RAG (저장소 루트에서)
source ./scripts/load-env-local.sh
cd rag-service
python3 -m venv .venv && source .venv/bin/activate   # 최초 1회
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8002

# 터미널 2 — Prompt
source ./scripts/load-env-local.sh
cd prompt-service
python3 -m venv .venv && source .venv/bin/activate   # 최초 1회
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8001

# 터미널 3 — AI Gateway
source ./scripts/load-env-local.sh
cd resume-ai
python3 -m venv .venv && source .venv/bin/activate   # 최초 1회
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

이미 `.venv`가 있으면 `source .venv/bin/activate`만 하면 됩니다.

### 1-4. Spring API (터미널 1개)

아래는 **저장소 루트**(`resume-pilot/`)에서 실행합니다. 이미 `resume-api/` 안이라면 `cd ..`로 루트로 나온 뒤 진행하세요.

```bash
# 저장소 루트에서
source ./scripts/load-env-local.sh
cd resume-api
chmod +x ./gradlew   # permission denied 날 때만 1회
./gradlew bootRun
```

### 1-5. 프론트엔드 (터미널 2개)

```bash
# 터미널 — Web
cd resume-web
npm install
npm run dev
# → http://localhost:5173

# 터미널 — Admin
cd resume-admin
npm install
npm run dev
# → http://localhost:5174/admin/
```

## 2. 배포 (Docker Compose)

프로덕션은 **5개 컨테이너**만 사용합니다.

| 컨테이너 | 역할 | 호스트 노출 |
|----------|------|-------------|
| app | Spring + SPA `/` + `/admin/` + API | `APP_PORT` |
| postgres | pgvector | `POSTGRES_PORT` (선택) |
| resume-ai | AI Gateway | 내부만 |
| prompt-service | Prompt runtime | 내부만 |
| rag-service | RAG / embedding | 내부만 |

### 2-1. Linux 서버

[설치-가이드.md § Part 3](설치-가이드.md#part-3-ubuntu-서버) 참고. 로컬 `.env`에 `DEPLOY_HOST`, `LAN_HOST` 설정.

```bash
cd ~/apps/resume-pilot
cp .env.production.example .env
./scripts/server-up.sh
```

### 2-2. Mac에서 원격 배포

```bash
# .env 에 DEPLOY_HOST 설정 후
./scripts/deploy-remote.sh
```

### 2-3. 로컬에서 prod 스모크 테스트

배포 전에 prod와 동일한 단일 app 컨테이너(SPA 번들 포함)를 띄울 때:

```bash
./scripts/local-prod-up.sh
# → http://localhost:8080/  http://localhost:8080/admin/
```

### 배포 접속 URL

`http://<LAN_HOST>:<APP_PORT>/` — `LAN_HOST`·`APP_PORT`는 서버 `.env` 참고 (기본 9180).

| 서비스 | Path |
|--------|------|
| Web | `/` |
| Admin | `/admin/` |
| API | `/api/v1` |
| Swagger | `/swagger-ui.html` |

### 유용한 명령 (서버)

```bash
cd ~/apps/resume-pilot
docker compose ps
docker compose logs -f app
docker compose up -d --build app    # app만 재빌드
./scripts/server-down.sh
```

## 3. 환경 변수 파일 정리

| 파일 | 용도 |
|------|------|
| `.env.example` | 로컬 터미널 개발 예시 (`localhost` URL) |
| `.env.production.example` | Docker 배포 예시 (컨테이너 간 `postgres` 호스트명) |
| `.env.local` | 로컬 개발 실제 값 (Git 제외). `source ./scripts/load-env-local.sh`로 세션에 로드 |
| `.env` | AI 서비스별 개별 설정 시드(`rag-service/.env` 등) 및 배포용 `DEPLOY_HOST`/`LAN_HOST` (Git 제외) |

## 4. 문제 해결

| 증상 | 확인 |
|------|------|
| API 401 | 로그인·토큰 만료 |
| AI 생성 실패 | resume-ai(8000), rag(8002) 실행 여부 |
| RAG 결과 없음 | 경험 저장 후 임베딩 생성 여부 |
| CORS | `RESUME_CORS_ORIGINS`에 `localhost:5173` 포함 |
| Flyway / DB 연결 타임아웃 | 원격 DB면 `ssh -L 55532:…` 터널이 살아 있는지, `.env.local`이 `localhost:55532`인지 확인 (§1-2 B) |
| 포트 충돌 | `./scripts/kill-port.sh 5173` (포트 번호 가능) |
| `cd backend` 실패 | API 디렉터리는 `resume-api` (`./gradlew bootRun`) |
| `.env.local`이 안 먹힘 | `source ./scripts/load-env-local.sh`로 로드했는지 확인 (직접 실행 금지) |

## 5. E2E 테스트 시나리오

### 회원가입 → 자소서 (Phase 1)

1. http://localhost:5173 → 회원가입
2. 이메일 인증: Admin 연동설정의 메일 발송이 `log`(또는 `.env` `MAIL_PROVIDER=log`)이면 API 로그의 `verifyUrl`을 브라우저에서 연다. Resend로 바꾸면 실제 메일로 인증. 상세: [연동-설정-가이드.md](연동-설정-가이드.md)
3. 소셜 로그인: Admin → `/admin/integration-settings`에 Google Client ID/Secret을 등록하면 로그인·가입 화면에 버튼이 나타난다. Redirect URI는 `http://localhost:8080/api/v1/auth/oauth/google/callback` (카카오는 비즈 이메일 권한 후 Admin에서 「로그인 화면 표시」켜기). 소셜 버튼 전에 이용약관·개인정보 동의가 필요하다. 상세: [연동-설정-가이드.md](연동-설정-가이드.md)
4. 자격 종목 조회: Admin → 연동설정 「자격 종목 조회」에서 사용 여부와 서비스 키를 등록 (공공데이터포털 Q-Net).
5. 경험 라이브러리에 프로젝트 2~3개 등록
6. 대시보드에서 자소서 생성 → 버전 diff 확인

### 공고 분석 (Phase 2)

1. 채용 공고 메뉴 → 텍스트/URL/PDF 업로드
2. 분석 결과·문체 분석 확인

### RAG + AI 생성 (Phase 3~4)

1. 워크스페이스 → 관련 경험 추천 → 자소서 생성
2. 품질 점수, AI 흔적, 첨삭, 면접 질문 확인

### 관리자 (Phase 5)

1. DB에서 role을 `ADMIN`으로 변경
2. http://localhost:5174 → Prompt/금지표현/사용자 관리

### 푸시 전 프론트 빌드 (권장)

`npm run dev`는 TypeScript 검사를 하지 않습니다. GitHub CI는 Docker 빌드 시 `npm run build`(tsc)를 실행합니다. 푸시 전에 아래를 한 번 돌리면 타입 오류를 미리 잡을 수 있습니다.
