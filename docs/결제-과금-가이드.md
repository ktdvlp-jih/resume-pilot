# ResumePilot 결제·과금 가이드

토스페이먼츠 키 등록부터 상품·구매·AI 차감·취소·단위 테스트까지 운영 순서를 정리한다.

관련: [토스페이먼츠_이식_가이드.md](토스페이먼츠_이식_가이드.md) (이식 설계), [API-규약.md](API-규약.md), [관리자-가이드.md](관리자-가이드.md), [사용자-가이드.md](사용자-가이드.md)

## 1. 개념

| 단위 | 설명 |
|------|------|
| **토큰** | 가상 재화. 기능마다 고정 단가 차감 (LLM 실사용량 아님) |
| **횟수** | 기능(`GENERATE`, `AI_REVIEW` 등)별 N회. 있으면 토큰보다 **우선** |
| **로트** | 지급 단위. FIFO로 소비. 결제 취소 시 **남은 로트만** 회수 |

차감 대상: 생성·탐지·윤문·첨삭·면접·키워드·포트폴리오·문항분석·공고분석.  
비과금: `EMBEDDING`, 생성 시 딸려 가는 문체 분석, 관리자(`ADMIN` / `JOB_ADMIN` / `USER_ADMIN`).

토스 시크릿·`paymentKey`·`orderId`는 로그·채팅·Git에 넣지 않는다. 키는 `.env`가 아니라 DB `integration_configs`(AES-GCM)에만 둔다.

## 가격 정책

구독(정기결제)이 아니라 **Free 월 자동 지급 + 유료 팩 구매**다. Admin `/admin/billing-products`에서 가격·지급량을 조정할 수 있다.

| 티어(표시) | 실체 | 내용 | 가격 |
|---|---|---|---|
| **Free** | 매월 `FREE_MONTHLY` 로트 | GENERATE 2회 + JOB_ANALYSIS 1회 + 토큰 50 | ₩0 |
| **스타터** | 팩 구매 | 토큰 100 **또는** 생성 10회 | ₩1,000 / ₩3,000 |
| **스탠다드** | 팩 묶음 표시 | 토큰 500 + (선택) 첨삭 10회 | ₩4,500~ / ₩2,000 |
| **파워** | 대용량 | 토큰 1000 | ₩8,000 |

규칙:

- Free는 결제 없이 가입 직후·월 스케줄로 지급. 이미 해당 `period_key`(UTC `YYYY-MM`)면 중복 지급하지 않는다.
- 다음 달 지급 전 남은 Free 로트는 만료(잔여 0) 후 재지급한다.
- 유료·관리자 지급 로트는 Free와 별도 FIFO(횟수 우선은 기존과 동일).
- 랜딩·`/pricing` 상단 티어 카드와 이 표를 맞춘다.

## 2. 사전 준비

1. 로컬/서버에서 API·Web·Admin이 떠 있는지 확인 ([실행-가이드.md](실행-가이드.md)).
2. [토스페이먼츠 개발자센터](https://developers.tosspayments.com/)에서 **테스트** 키 발급.
   - 클라이언트 키: `test_` 로 시작 (브라우저 결제창)
   - 시크릿 키: 서버 승인·취소 전용
3. 결제 허용 도메인에 `localhost`(로컬), 운영 호스트를 등록.
4. 로컬은 **`localhost` + SDK v2**. `127.0.0.1`만 쓰면 Referer로 막힐 수 있다.
5. 테스트 키와 라이브 키를 섞지 않는다.

## 3. 관리자: API(연동) 키 등록

경로: `http://localhost:5174/admin/integration-settings` (운영은 `/admin/integration-settings`)

1. `ADMIN`으로 로그인.
2. **연동 설정** → PG · 토스페이먼츠.
3. `TOSS_PAYMENTS_CLIENT_KEY`에 클라이언트 키 입력.
4. `TOSS_PAYMENTS_SECRET_KEY`는 「키 수정」 후 시크릿 입력.
5. **저장**.
6. 다시 열어 시크릿이 마스킹(`test…xxxx`)으로만 보이는지 확인.
7. 마스크 상태에서 저장해도 시크릿이 `***`로 덮이지 않는지 확인(한 번 더 저장).

API로 확인할 때:

```bash
# 공개 — 시크릿이 응답에 없어야 함
curl -s http://localhost:8080/api/v1/payments/client-key
# → { "success": true, "data": { "clientKey": "test_ck_..." } }
```

키가 비어 있으면 사용자 결제창이 열리지 않고 「관리자가 연동 설정에서…」 안내가 나온다.

## 4. 관리자: 상품·단가

경로: `/admin/billing-products`

### 4-1. 상품

- **TOKEN**: `grantAmount` = 지급 토큰 수, `operation` 없음
- **COUNT**: `operation` = `LlmOperation` 문자열 (예: `GENERATE`), `grantAmount` = 횟수
- `priceKrw`: 결제 금액(원). 주문 시 **서버가 DB 금액을 씀** (클라이언트 조작 불가)
- `enabled=false`면 공개 목록·주문에서 제외

시드 예: 토큰 100/500/1000, 자소서 생성 10회, AI 첨삭 10회.

### 4-2. 기능별 토큰 단가

같은 화면 하단. 기본값 예:

| operation | token_cost |
|-----------|------------|
| GENERATE | 50 |
| JOB_ANALYSIS | 20 |
| AI_REVIEW | 20 |
| AI_HUMANIZE | 15 |
| INTERVIEW_QUESTIONS | 20 |
| PORTFOLIO_REVIEW | 20 |
| AI_DETECTION | 10 |
| KEYWORD_COMPARE | 10 |
| SECTION_ANALYSIS | 10 |

## 5. 사용자: 구매 흐름

1. 로그인 후 `/billing` (또는 `/pricing` → 충전 CTA).
2. 잔액(토큰·횟수)과 상품 목록 확인. 헤더에 토큰 잔액 뱃지.
3. **구매하기** → 서버 `POST /payments/orders` → Toss SDK v2 결제창.
4. 성공 시 `/billing/complete?paymentKey&orderId&amount`
   - 프론트가 `POST /payments/confirm` **1회**
   - `sessionStorage`로 새로고침 중복 호출 완화
   - 서버 `order_id` unique로 이중 지급 방지
5. 실패 시 `/billing/fail` — confirm 호출 없음.

검수:

- [ ] 클라이언트가 `amount`를 바꿔 confirm하면 `PAYMENT_AMOUNT_MISMATCH`
- [ ] 같은 `orderId` 두 번 confirm해도 이중 지급 없음
- [ ] fail 페이지에서 confirm 없음

## 6. AI 사용·차감

1. Workspace 생성·탐지·첨삭 등 또는 채용공고 분석.
2. 해당 기능 **횟수 잔여가 있으면 1회 차감**, 없으면 단가만큼 **토큰** 차감.
3. 부족하면 `402 INSUFFICIENT_BALANCE` — `/billing`에서 충전.
4. AI 호출 실패 시 서버가 홀드를 환급(같은 트랜잭션/후속 refund).

관리자가 테스트할 때: **사용자** 메뉴 → **잔액·지급**으로 토큰/횟수 수동 지급 가능.

---

## 7. 관리자: 결제 취소

경로: `/admin/payments`

1. `COMPLETED` 행에서 **취소**.
2. 토스 전액 취소 후, 해당 결제에 묶인 **남은 로트만** 0으로 회수.
3. 이미 쓴 토큰/횟수는 회수하지 않음.
4. 회수 실패 시 ledger에 수동 보정 플래그(`needs_manual_fix`).

## 8. API 요약

| Method | Path | Auth | 설명 |
|--------|------|------|------|
| GET | `/api/v1/payments/client-key` | 공개 | 클라이언트 키만 |
| GET | `/api/v1/billing/products` | 공개 | enabled 상품 |
| GET | `/api/v1/billing/wallet` | 회원 | 잔액·단가 |
| POST | `/api/v1/payments/orders` | 회원 | 주문 (금액=서버) |
| POST | `/api/v1/payments/confirm` | 회원 | 승인+지급 |
| GET/PATCH | `/api/v1/admin/integration-settings` | ADMIN | 키 |
| GET/PUT | `/api/v1/admin/billing/products` | ADMIN | 상품 |
| GET/PATCH | `/api/v1/admin/billing/operation-costs/{op}` | ADMIN | 단가 |
| GET | `/api/v1/admin/payments` | ADMIN | 결제 목록 |
| POST | `/api/v1/admin/payments/{id}/cancel` | ADMIN | 전액 취소 |
| GET/POST | `/api/v1/admin/users/{id}/wallet` · `…/entitlements` | ADMIN·USER_ADMIN | 잔액·수동 지급 |

에러: `INSUFFICIENT_BALANCE`(402), `PAYMENT_NOT_CONFIGURED`(503), `PAYMENT_AMOUNT_MISMATCH`(400), `PAYMENT_ALREADY_PROCESSING`(409).

## 10. 운영 체크리스트

- [ ] 시크릿이 브라우저 네트워크·콘솔·서버 로그에 없다
- [ ] 마스크 저장이 시크릿을 덮지 않는다
- [ ] `GET client-key`에 시크릿 없음
- [ ] 주문 금액은 서버 상품 기준
- [ ] 테스트 카드로 complete → confirm → 잔액 반영
- [ ] amount 조작 confirm → 거절
- [ ] 동일 orderId 재confirm → 이중 지급 없음
- [ ] AI 1회: 횟수 있으면 횟수, 없으면 토큰
- [ ] 잔액 0이면 AI 차단
- [ ] 관리자 전액 취소 → 잔여 로트만 회수
- [ ] fail 페이지는 confirm 없음
- [ ] 단위 테스트 `billing.*` 통과
