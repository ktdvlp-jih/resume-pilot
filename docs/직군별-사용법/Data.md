# 데이터 직군 사용법

회원가입 다음 「경험 라이브러리」 → 「채용 공고」 → 「워크스페이스」 순서입니다. 근거가 없으면 「내용이 부족하여 생성하지 않음」이 정상입니다.

## 1. 이 직군에서 공고 고르기

데이터 분석·엔지니어링·사이언스 공고를 올립니다. 제목·마감일·캘린더 순서는 [공고 올리는 법](/guides/job-posting)을 보세요. 담당 업무·자격·우대처럼 있는 칸만 넣고, 지원 버튼·개인정보는 빼도 됩니다.

## 2. 경험 칸

이 직군은 아래 유형이 잘 맞습니다. 칸 채우는 법은 [경험 나누어 쓰기](/guides/star)를 보세요. 안 한 일과 없는 숫자는 비웁니다.

- **프로젝트** 데이터를 모으고 쓰이게 한 일. 상황: 왜 그 데이터가 필요했는지 / 과제: 목표·제약 / 행동: 어떤 흐름을 만들었는지 / 결과: 달라진 점 / 기술: 실제로 쓴 도구만
- **문제 해결** 정의를 다시 써서 제품이나 운영이 바뀐 일. 상황: 처음에 무엇이 문제로 보였는지 / 과제: 맞춰야 할 목표 / 행동: 문제를 어떻게 다시 썼는지 / 결과: 무엇이 바뀌었는지
- **성과** 실험이나 모델이 남긴 결과. 상황: 왜 실험·모델이 필요했는지 / 과제: 검증 목표 / 행동: 어떤 설계를 했는지 / 결과: 남은 것 / 수치 성과: 없으면 비움

프로젝트명·기간·역할은 본인 사실만 적습니다.

## 3. 워크스페이스에서 고르기

생성에 쓰는 경험은 2~5개입니다. 「생성 준비됨」이 3개 이상이면 고르기 쉽습니다. 설명 80자 이상, 역할, 성과 또는 상황·과제·행동·결과가 있어야 합니다. 공고에 적힌 도구를 그 일에 안 썼으면 기술 칸에 넣지 마세요. 생성이 끝나면 「AI 흔적 다듬기」를 직접 누릅니다. 사실과 숫자는 그대로입니다.

## 4. 「내용이 부족하여 생성하지 않음」이 나오면

빈 칸이면 생성을 안 하는 것이 정상입니다. 배지는 「내용 보강 필요」입니다. 지원 동기·입사 가능 일자는 경험 카드가 아닙니다. 문항 답안 전문도 만들지 않습니다.

프로젝트는 본인이 이은 데이터 흐름, 문제 해결은 정의가 결정으로 이어진 점, 성과는 실험·모델이 남긴 것만 보강합니다.

## 5. 좋은 한 줄 vs 나쁜 한 줄

좋음: 배치가 새벽에 끊겨 알람 조건을 바꾸고, 같은 주 장애는 내가 롤백까지 했다.  
나쁨: 공고에 있는 도구 이름을 나열하고 파이프라인을 운영했다고 씀.

좋음: 이탈로 보이던 지표를 가입 오류로 다시 쓰고, 가입 화면 문구를 바꾸는 쪽으로 합의했다.  
나쁨: 없는 가입자 수와 매출을 분석 성과로 붙임.
