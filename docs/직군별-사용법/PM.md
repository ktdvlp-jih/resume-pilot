# PM 직군 사용법

회원가입 다음 `/experiences` → `/job-postings` → `/workspace` 순서입니다. 근거가 없으면 「내용이 부족하여 생성하지 않음」이 정상입니다.

## 1. 공고 올리는 법

PM은 채용 페이지의 프로덕트·기획 JD를 URL로 올리는 편이 안전합니다. 텍스트 붙여넣기, PDF·PNG·JPG도 됩니다. 이미지 OCR이 나쁘면 텍스트나 URL을 쓰세요.

예시: 당근 Product Manager - 중고거래  
https://about.daangn.com/jobs/4772916003/ (수집일 2026-08-25, 22:35 KST)

자소서 문항은 없고 자유형식 이력서입니다. 데이터로 가설을 세우고 A/B로 검증한 경험, 0 to 1 성과, AI로 제품을 운영한 일을 적으라고 합니다. 안 한 일은 비웁니다. 팀 소개·담당 업무·자격·우대까지 넣고, 지원 버튼·개인정보는 빼도 됩니다.

## 2. 경험 타입과 STAR 빈칸

데모 계정 `demo-pm` 세 장입니다. 지금은 모두 «내용 보강 필요», 사실 칸은 TBD, `numeric_result`는 공란입니다. 운영 계정에 넣지 마세요.

- **LEADERSHIP** 문제 정의와 방향 결정. situation 어떤 문제·기회였는지 / task 목표와 제약 / action 문제를 어떻게 정의했고 무엇을 안 만들기로 했는지 / result 결과와 러닝 / skills 실제로 쓴 방법·도구만
- **COLLABORATION** 직군·이해관계자와 요구사항 맞추기. situation 누구와 무엇이 안 맞았는지 / task 맞출 목표 / action 어떻게 구조화·번역·합의했는지 / result 스펙 또는 운영 결과 / skills SQL·Tableau는 썼을 때만
- **CONFLICT_RESOLUTION** 우선순위 충돌 정리와 합의. situation 어떤 요구가 충돌했는지 / task 제약 / action 판단 기준과 무엇을 안 하기로 했는지 / result 합의와 러닝 / numeric_result 없으면 비움

프로젝트명·기간·역할은 본인 사실만. 당근·토스·카카오에서 일한 것처럼 쓰지 마세요. 공식 직함이 아니면 팀장·PO를 붙이지 마세요.

## 3. 워크스페이스에서 2~5개 고르는 기준

생성에 쓰는 경험은 2~5개입니다. 그전에 «생성 준비됨»이 3개 이상이어야 합니다. 설명 80자 이상, 역할 있음, 성과 또는 STAR가 충분해야 합니다. 없는 수치는 공란입니다. 공고 우대(SQL, Tableau, POS, AI 프로덕트, 마켓플레이스)를 안 했으면 skills에 넣지 마세요. 지금은 세 장 모두 보강 필요이므로 이름·기간·역할·실제 도구를 채운 뒤에 고릅니다.

## 4. 「내용이 부족하여 생성하지 않음」이 나오면

이번 사이클 공고에는 자소서 문항이 없습니다. 빈 칸이면 생성을 안 하는 것이 정상입니다. 배지는 그대로 «내용 보강 필요»입니다.

이력서에 쓸 때는 문제 정의 → 가설 → 검증 → 결과 순이면 충분합니다. LEADERSHIP은 방향과 본인이 설득한 범위, COLLABORATION은 상대 직군과 산출물, CONFLICT_RESOLUTION은 충돌의 실체와 합의를 채우세요. 0 to 1·AI 제품·A/B·GMV를 안 했으면 만들지 마세요. 문항 답안 전문은 만들지 않습니다.

## 5. 좋은 한 줄 vs 나쁜 한 줄

좋음: 신규 기능을 세 개 요청받아 목표 지표에 안 맞는 두 개를 접고, 남은 하나를 출시 범위로 합의했다.  
나쁨: SQL, Tableau로 중고거래 GMV를 20% 성장시켰다. (공고 우대·없는 숫자)

좋음: 디자인 일정과 개발 공수가 충돌해 이번 스프린트에서 알림을 빼기로 했다.  
나쁨: 0 to 1 마켓플레이스를 AI로 만들어 운영했다. (안 한 도메인·스택)
