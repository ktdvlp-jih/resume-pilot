# 백엔드 직군 사용법

회원가입 다음 「경험 라이브러리」 → 「채용 공고」 → 「워크스페이스」 순서입니다. 근거가 없으면 「내용이 부족하여 생성하지 않음」이 정상입니다.

## 1. 이 직군에서 공고 고르기

서버·플랫폼·인프라 공고를 올립니다. 제목·마감일·캘린더 순서는 [공고 올리는 법](/guides/job-posting)을 보세요. 담당 업무·자격·우대처럼 있는 칸만 넣고, 지원 버튼·연락처는 빼도 됩니다.

## 2. 경험 칸

이 직군은 아래 유형이 잘 맞습니다. 칸 채우는 법은 [경험 나누어 쓰기](/guides/star)를 보세요. 안 한 일과 없는 숫자는 비웁니다.

- **프로젝트** 시스템을 만들고 옮기거나 범위를 나눈 일. 상황: 왜 그 일이 필요했는지 / 과제: 목표·제약 / 행동: 어떤 경계를 골랐는지 / 결과: 달라진 점 / 기술: 실제로 쓴 언어·프레임워크만
- **기술** 성능·호환·원인을 검증한 일. 상황: 어떤 문제였는지 / 과제: 원인 찾기 또는 시험 / 행동: 무엇을 쟀는지 / 결과: 도입했는지 / 기술: 그때 쓴 도구만
- **문제 해결** 트래픽·동시성·장애처럼 막힌 구간. 상황: 실제로 겪은 문제 / 과제: 맞춰야 할 목표 / 행동: 왜 그 방법을 골랐는지 / 결과: 성과와 재발 여부 / 수치 성과: 없으면 비움

프로젝트명·기간·역할은 본인 사실만 적습니다.

## 3. 워크스페이스에서 고르기

생성에 쓰는 경험은 2~5개입니다. 「생성 준비됨」이 3개 이상이면 고르기 쉽습니다. 설명 80자 이상, 역할, 성과 또는 상황·과제·행동·결과가 있어야 합니다. 공고에 적힌 기술을 그 일에 안 썼으면 기술 칸에 넣지 마세요. 생성이 끝나면 「AI 흔적 다듬기」를 직접 누릅니다. 사실과 숫자는 그대로입니다.

## 4. 「내용이 부족하여 생성하지 않음」이 나오면

빈 칸이면 생성을 안 하는 것이 정상입니다. 배지는 「내용 보강 필요」입니다. 지원 동기·입사 가능 일자·공고를 접한 경로는 경험 카드가 아닙니다. 문항 답안 전문도 만들지 않습니다.

프로젝트는 이름과 본인이 한 범위, 기술은 대상과 실제로 잰 것, 문제 해결은 문제 → 왜 그 방법 → 결과만 보강합니다.

## 5. 좋은 한 줄 vs 나쁜 한 줄

좋음: 동시성으로 재고가 어긋나 락 범위를 좁히고, 같은 증상이 다시 안 나게 가드를 남겼다.  
나쁨: 공고에 있는 기술 이름을 나열하고 안 한 도메인을 구축했다고 씀.

좋음: 프로파일러로 핫스팟을 본 뒤 후보 기술을 이번엔 넣지 않기로 했다.  
나쁨: 지원 동기를 경험 설명에 지어냄.
