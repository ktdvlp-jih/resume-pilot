# 자소서 날조 방지 체크리스트

AI가 자소서를 “잘 못 써서”가 아니라, **넘긴 경험에 없는 디테일을 분량·문항 서사에 맞춰 채울 때** 거짓이 생깁니다. 생성 전에 아래를 확인하세요.

## 1. 경험 라이브러리 (가장 중요)

| 항목 | 통과 기준 | 부족 시 증상 |
|------|-----------|--------------|
| 건수 | 「생성 준비됨」 **≥ 3** | 같은 경험 반복·과장 |
| 설명 | **≥ 80자** | 역할·기술 날조 |
| 역할 | 비어 있지 않음 | “주도/리더” 과장 |
| 성과 | 성과 ≥ 10자 **또는** STAR 합 ≥ 40자 | 수치·성과 날조 |
| 수치 | 없는 수치는 **공란** | “40% 단축” 같은 허구 |
| 시점 | 실무/학창·기간이 경험에 명시 | 학창↔실무 시점 이동, 기간 없는 ‘곧바로’ 단정 |
| 기술 | 실제 스택만 skills에 | 공고 스택을 경험에 끼워 넣음 |

경험 목록의 **활용도** 배지: `생성 준비됨` / `내용 보강 필요` / `제목 위주`.

## 2. 워크스페이스 생성 입력

| 항목 | 통과 기준 |
|------|-----------|
| 경험 선택 | **준비됨 경험 2~5개** 직접 선택 (미선택·제목만 → 생성 차단) |
| 공고 | 분석된 공고 또는 JD 본문 |
| Rewrite | **30~50** 권장 (70 이상이면 표현만 바뀌고 사실은 그대로여야 함) |
| 문항 | 성장과정만 단독 생성 지양 (학창 근거 없으면 일반론만) |
| 임베딩 | 경험 수정 후 **RAG 인덱스 갱신** |

워크스페이스 3단계에 **생성 전 점검** 패널이 표시됩니다.

## 3. 결과가 의심될 때

- 라이브러리에 없는 프로젝트명·수치·시점이 있으면 → 경험을 보강하거나 Rewrite를 낮추고 재생성
- “내용이 부족하여 생성하지 않음” → **정상** (근거가 부족함)
- 추천이 공고와 안 맞으면 → 공고 분석·RAG 인덱스 갱신 후 다시 추천
