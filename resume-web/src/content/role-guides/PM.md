# 기획 직군 사용법

회원가입 다음 「경험 라이브러리」 → 「채용 공고」 → 「워크스페이스」 순서입니다. 근거가 없으면 「내용이 부족하여 생성하지 않음」이 정상입니다.

## 1. 이 직군에서 공고 고르기

제품·기획 공고를 올립니다. 제목·마감일·캘린더 순서는 [공고 올리는 법](/guides/job-posting)을 보세요. 담당 업무·자격·우대처럼 있는 칸만 넣고, 지원 버튼·개인정보는 빼도 됩니다.

## 2. 경험 칸

이 직군은 아래 유형이 잘 맞습니다. 칸 채우는 법은 [경험 나누어 쓰기](/guides/star)를 보세요. 안 한 일과 없는 숫자는 비웁니다.

- **리더십** 문제 정의와 방향 결정. 상황: 어떤 문제·기회였는지 / 과제: 목표와 제약 / 행동: 문제를 어떻게 정의했고 무엇을 안 만들기로 했는지 / 결과: 결과와 배운 점 / 기술: 실제로 쓴 방법만
- **협업** 직군·이해관계자와 요구사항 맞추기. 상황: 누구와 무엇이 안 맞았는지 / 과제: 맞출 목표 / 행동: 어떻게 정리하고 합의했는지 / 결과: 합의한 범위 또는 운영 결과 / 기술: 썼을 때만
- **갈등 해결** 우선순위 충돌 정리와 합의. 상황: 어떤 요구가 충돌했는지 / 과제: 제약 / 행동: 판단 기준과 무엇을 안 하기로 했는지 / 결과: 합의와 배운 점 / 수치 성과: 없으면 비움

프로젝트명·기간·역할은 본인 사실만 적습니다. 공식 직함이 아니면 팀장·제품 책임자를 붙이지 마세요.

## 3. 워크스페이스에서 고르기

생성에 쓰는 경험은 2~5개입니다. 「생성 준비됨」이 3개 이상이면 고르기 쉽습니다. 설명 80자 이상, 역할, 성과 또는 상황·과제·행동·결과가 있어야 합니다. 공고 우대 도구를 안 썼으면 기술 칸에 넣지 마세요. 생성이 끝나면 「AI 흔적 다듬기」를 직접 누릅니다. 사실과 숫자는 그대로입니다.

## 4. 「내용이 부족하여 생성하지 않음」이 나오면

빈 칸이면 생성을 안 하는 것이 정상입니다. 배지는 「내용 보강 필요」입니다. 지원 동기·입사 가능 일자는 경험 카드가 아닙니다. 문항 답안 전문도 만들지 않습니다.

리더십은 방향과 본인이 설득한 범위, 협업은 상대 직군과 산출물, 갈등 해결은 충돌의 실체와 합의만 보강합니다. 안 한 제품·실험·거래액은 만들지 마세요.

## 5. 좋은 한 줄 vs 나쁜 한 줄

좋음: 신규 기능을 세 개 요청받아 목표 지표에 안 맞는 두 개를 접고, 남은 하나를 출시 범위로 합의했다.  
나쁨: 공고 우대 도구와 없는 성장 숫자를 붙임.

좋음: 디자인 일정과 개발 공수가 충돌해 이번 개발 주기에서 알림을 빼기로 했다.  
나쁨: 안 한 제품·기술을 처음부터 만든 것처럼 씀.
