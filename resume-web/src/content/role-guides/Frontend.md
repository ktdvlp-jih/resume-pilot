# 프론트엔드 직군 사용법

회원가입 다음 「경험 라이브러리」 → 「채용 공고」 → 「워크스페이스」 순서입니다. 근거가 없으면 「내용이 부족하여 생성하지 않음」이 정상입니다.

## 1. 이 직군에서 공고 고르기

웹·화면·앱 공고를 올립니다. 제목·마감일·캘린더 순서는 [공고 올리는 법](/guides/job-posting)을 보세요. 담당 업무·자격·우대처럼 있는 칸만 넣고, 지원 버튼·개인정보는 빼도 됩니다.

## 2. 경험 칸

이 직군은 아래 유형이 잘 맞습니다. 칸 채우는 법은 [경험 나누어 쓰기](/guides/star)를 보세요. 안 한 일과 없는 숫자는 비웁니다.

- **프로젝트** 사용자 문제를 화면으로 푼 기여. 상황: 어떤 사용자 문제였는지 / 과제: 목표와 제약 / 행동: 어떤 화면·흐름을 왜 그렇게 만들었는지 / 결과: 결과와 배운 점 / 기술: 실제로 쓴 언어·프레임워크만
- **기술** 접근성·성능·렌더링을 검증한 일. 상황: 어떤 문제였는지 / 과제: 검증 목표 / 행동: 무엇을 측정하고 비교했는지 / 결과: 도입했는지 / 기술: 이 검증에서 쓴 것만
- **협업** 직군 간 소통과 막힌 구간. 상황: 일정·스펙·인터페이스 중 무엇이 안 맞았는지 / 과제: 맞출 목표 / 행동: 누구와 무엇을 어떻게 맞췄는지 / 결과: 합의·전달·품질 / 기술: 없어도 됨

프로젝트명·기간·역할은 본인 사실만 적습니다.

## 3. 워크스페이스에서 고르기

생성에 쓰는 경험은 2~5개입니다. 「생성 준비됨」이 3개 이상이면 고르기 쉽습니다. 설명 80자 이상, 역할, 성과 또는 상황·과제·행동·결과가 있어야 합니다. 공고에 적힌 기술을 그 일에 안 썼으면 기술 칸에 넣지 마세요. 생성이 끝나면 「AI 흔적 다듬기」를 직접 누릅니다. 사실과 숫자는 그대로입니다.

## 4. 「내용이 부족하여 생성하지 않음」이 나오면

빈 칸이면 생성을 안 하는 것이 정상입니다. 배지는 「내용 보강 필요」입니다. 지원 동기·입사 가능 일자·지원 경로는 경험 카드가 아닙니다. 문항 답안 전문도 만들지 않습니다.

프로젝트는 이름과 본인 기여 범위, 기술은 대상 화면과 측정·검토한 것, 협업은 상대 직군과 맞춘 결과만 보강합니다. 안 한 화면은 만들지 마세요.

## 5. 좋은 한 줄 vs 나쁜 한 줄

좋음: 검색 결과 첫 화면이 느려 렌더링 방식을 비교한 뒤, 익숙한 서버 렌더를 이번엔 쓰지 않기로 했다.  
나쁨: 공고에 있는 기술 이름을 복사해 웹을 구축했다고 씀.

좋음: 디자인 시안과 API 필드가 어긋나 기획·서버와 필드를 맞춰 빈 상태를 먼저 그렸다.  
나쁨: 지원 동기를 경험 설명에 지어냄.
